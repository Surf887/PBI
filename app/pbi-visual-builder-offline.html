          How to use it

            Custom visual with the Power BI Visuals SDK

            Only for a reusable visual needed in many reports, with an owner, a code review and a route into your organizational store. Installing Node.js and the SDK needs your IT department's approval.

            • No network calls, eval, string timers or innerHTML; keep privileges empty.
            • Support rendering events, selection, context menu, tooltips, keyboard focus, high contrast and a landing page.
            • Package with --certification-audit and give the reviewed .pbiviz to your Power BI admin for the organizational store.

            Scan files for unsafe content

            Checks for external URLs, scripts and event handlers, remote CSS, dynamic code, network privileges and pre-encoded colours in DAX: the same rules as the skill's scanner. Point it at a PBIP project, a pbiviz project or single files. Files are only read.

            Safety rules

            1. No external references. No http(s):// in SVG, Deneb specs, HTML, CSS, themes or code; only data: URIs. Schema URLs and the SVG namespace are identifiers, not requests.
            2. No executable content. No <script>, event handlers, javascript:, <foreignObject>, <iframe>, eval, string timers or innerHTML with data.
            3. Escape data. XML-escape text placed in SVG or HTML; build JSON with a serializer; double single quotes in PBIR text literals.
            4. Certified first. Built-in visual, then certified AppSource visuals (Deneb, HTML Content Secure), then your organizational store. Never side-load .pbiviz files or use non-certified builds in production.
            5. Respect tenant controls. Do not work around "certified visuals only" or other admin settings; ask your admin.
            6. Keep data out. Work from field names. Never share .pbi/cache.abf, .pbix files or data exports: they contain data.
            7. No secrets in files, specs or measures.
            8. Safe edits. Edit PBIP files only with Desktop closed and the project in Git or backed up. Parse and write JSON with code, never by hand-editing escaped text.

            Design

            • The title states the takeaway; units appear once; format strings are consistent.
            • Bars start at zero; sort meaningfully; label directly instead of using legends where possible.
            • Colour carries meaning: one colour per measure, red and green only for bad and good, no more than 6 categorical colours, never colour alone.
            • Alt text on every visual, sensible tab order, text contrast of at least 4.5:1, and a number next to every SVG image.
            • No more than 8 to 10 visuals per page; aggregate in DAX; measure with Performance Analyzer.

            Before you publish

            1. Every JSON file parses; PBIR files keep the $schema version your project already uses.
            2. The Scan tab finds nothing in the files you changed.
            3. Deneb specs compile in the Deneb editor without warnings, and field names match the Values well.
            4. SVG measures: Data category is Image URL; the worst case stays well under 32,000 characters (LEN).
            5. Reopen the report in Desktop and look at the result.
